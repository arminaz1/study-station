## 1. Scenario

The program starts and loads `sessions.csv` if it exists. It then asks for an activity name and a start time. When both are valid, it records that the session has started. It asks for the end time, builds the Session, saves all sessions, and prints them. The next run loads the saved sessions again.

If the program is killed after the start time was entered, the next run finds an unfinished-session record, reports it, and discards it.

Steps:
1. Load `sessions.csv` into the containers that `main()` owns. A missing file means an empty list. A last line without a final newline is ignored and reported. A broken line anywhere else stops the program (step 8).
2. Check for `active_session.csv`. If it exists, report its name and start, then remove it. The session is not added to `sessions.csv`.
3. Read the activity name and the start time. Check the name with `Activity::create` and the start (0 or more). Only then write `active_session.csv`.
4. Read the end time. Create the Session as in v0.1.
5. Save all sessions to `sessions.csv` (temp file, then rename).
6. Remove `active_session.csv`.
7. Print all sessions and exit with code 0.
8. On any failure, print the reason to `std::cerr` and exit with code 1.

## 2. Requirements

- R2-1. One session is one line in `sessions.csv`: activity name, start, end. Times are integer seconds. No header line. Every line ends with a newline.
- R2-2. Saving writes the complete list to `sessions.csv.tmp`, flushes and closes it, checks that every step worked, and only then renames it over `sessions.csv`. Nothing is ever written directly into `sessions.csv`. A leftover `.tmp` from a crash is never read by load. The next save overwrites it.
- R2-3. A missing `sessions.csv` is not an error: the list starts empty. An empty file also gives an empty list.
- R2-4. The last line of the file counts only if it ends with a newline. A last line without one is ignored, even if it looks valid. The program reports it, and all earlier sessions are kept. (Decision Q6.)
- R2-5. Every loaded line is checked with the same rules as v0.1 (non-empty name, start 0 or more, end not before start). Reuse `Activity::create` and `Session::create`. Do not copy the rules.
- R2-6. A malformed line that is not the last line stops the load with an error. The error names the line number and shows the line's text. Nothing is saved, `sessions.csv` stays unchanged, `main()` prints the error to `std::cerr` and exits with code 1. (Decision Q7.)
- R2-7. When a session starts, `active_session.csv` is written with one line: activity name, start. It uses the same temp-then-rename method as R2-2. It is written only after the name passed `Activity::create` and the start is 0 or more. It is removed when the session has been saved.
- R2-8. At startup, an existing `active_session.csv` is reported with its name and start, then removed. The session is not added to `sessions.csv`. If the record cannot be read, that is reported too, and it is removed. (Decision Q5.)
- R2-9. No file code and no console code in `src/core`. Converting one session to a line and one line to a session may live in core only if it takes and returns plain values and strings. All stream and file operations live in `src/platform`.
- R2-10. `load` returns a status (`enum class`) and fills the containers that `main()` passes in by reference. `save` returns a status that names the failing step. `main()` reacts with a `switch` and prints errors to `std::cerr`. (Decision Q4.)
- R2-11. Times stay `long long`. No clock is read (v0.1 R9 still applies).
- R2-12. Activities live in a `std::deque<Activity>`, Sessions in a `std::vector<Session>`. Fixed-capacity storage comes in v0.8.
- R2-13. v0.1 behaviour is unchanged, except for R2-15. The v0.1 tests and C1 to C7 still pass.
- R2-14. The code builds with zero warnings under the flags in section 5 and runs with zero sanitizer reports.
- R2-15. `Activity::create` rejects a name that contains a comma, a carriage return, or a line feed. The rule lives in the core, so every Activity that exists can be saved. (Decision Q3.)
- R2-16. `main()` owns both containers and declares the Activity deque before the Sessions container. A Session keeps a `const Activity*` into the deque. No function returns a container of Sessions that points into another container. (Decision Q2.)
- R2-17. A number field in the file must be a whole number and nothing else. `12abc` and `1.5` are rejected.
- R2-18: If a line or console entry is rejected after its Activity was newly added to the deque, that Activity is removed again. An Activity that already existed stays.

## 4. New terms (one line each)

- **CSV:** a text file with one record per line and the fields separated by commas.
- **File stream (`std::ofstream`, `std::ifstream`):** objects that write to or read from a file. Like `cin`, they have a failure state you can test.
- **Temp file and rename:** write the new content to a second file, then swap it in with one rename. The real file is then either the old complete version or the new complete version, never half of each. [Likely] On Windows with MinGW, `std::filesystem::rename` replaces an existing file. Check the result with A2-3.
- **Truncated:** cut off before the end, for example because power was lost during a write.
- **Flush:** push the program's buffered data to the operating system. It does not guarantee the data reached the disk. That needs a stronger call, covered in v1.4.
- **Round trip:** save then load gives back exactly the same data.
- **`std::deque`:** like a vector, but it stores elements in several separate blocks. Adding to the end never moves the existing elements, so pointers to them stay valid.
- **`enum class`:** a type with a fixed list of named values, such as `LoadStatus::BadLine`.
- **`struct`:** a bundle of named public fields.
- **Out-parameter:** a reference parameter that the function fills, so data comes back without being returned.
- **`const Activity*` versus `Activity* const`:** `const` before the `*` locks the box (read-only access), `const` after the `*` locks the arrow (cannot be re-aimed).
- **GDB breakpoint:** a marked line where GDB stops the running program so you can look at its variables.
- **GDB backtrace:** the list of function calls that led to the current line.

Known limits to record:
- Flush and rename on the PC do not guarantee that the data reached the disk after a real power cut. The flash version in v1.4 deals with this.
- A valid last line that only lacks its newline is dropped (R2-4).
- Activity names are not trimmed.
- Bad lines are never repaired or preserved. A later stage could keep them, for example in a `.bak` copy.

## 9. Decisions (the before-you-code questions)

| Q  | Decision                                                                                                     |
|----|--------------------------------------------------------------------------------------------------------------|
| Q1 | A line stores name, start and end. The Activity is created first, then the Session gets its address. A file stores values, never pointers. |
| Q2 | Activities in a `std::deque` (addresses stay stable on `push_back`), declared before the Sessions container. Sessions keep `const Activity*`. |
| Q3 | Reject comma, carriage return and line feed in `Activity::create`. The core owns the rule.                    |
| Q4 | `load` returns a status `enum class` and fills containers passed by reference. `save` returns a status naming the failing step. |
| Q5 | Unfinished session: report it, then discard it. Missing data is better than wrong data.                       |
| Q6 | The last line counts only if it ends with a newline. Detect with the stream's end-of-file state after `getline`. |
| Q7 | A bad line in the middle stops the load with an error naming the line number and text. Nothing is saved.      |
| Q8 | Two lines in the file both say `Reading`. They shall share one Activity object in the deque. |
